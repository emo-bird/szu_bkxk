## 二、鉴权与身份参数处理逻辑
> 原token逻辑保留，**新增4项身份凭证全部由用户从浏览器登录页面复制粘贴输入，程序不实现登录、不处理人机验证码**
1. UI新增4个输入控件，和Token输入框放在同一区域：
    - `studentCode`：学号输入框
    - `electiveBatchCode`：选课批次编码输入框
    - `cookie`：完整Cookie字符串大文本输入框（支持多行粘贴）
    - `token`：原有sessionStorage.token输入框保留
2. 该token保存在前端`sessionStorage.token`，程序必须模拟设置该sessionStorage环境。
3. 网页行为特征：**不是所有请求的URL query都要带上token**，部分页面URL会自动拼接token，部分接口没有；不能统一给全部请求强制在get参数追加token；请求参数、鉴权逻辑全部通过逆向网页JS与网络请求确定，可参考szu仓库header。
4. 所有网络请求模块统一读取这四份凭证；凭证不硬编码；UI可以清空/修改；网络模块做参数空值校验，缺失任意关键凭证直接输出日志告警，拒绝发起请求。

## 三、UI整体布局：采用标签页/分区界面
### 标签页1｜课程查询面板
1. Token输入控件区域扩展为一组凭证输入框：studentCode、electiveBatchCode、cookie、token，用于粘贴浏览器复制得到的身份信息。
2. 课程表格展示字段：课程号，课程总号，课程名称，课程类别，课程性质，开课单位，学分，课程时间，是否MOOC，已选人数 / 总人数。
3. 表格支持：自定义勾选显示/隐藏表格列，可按需开启关闭各个维度。
4. 功能按钮：
    - 【刷新查询】：手动触发调用课程查询接口，更新表格；**该手动操作为最高请求优先级**
    - 筛选组件：支持多条件筛选课程列表，支持课程名模糊搜索等；筛选可以前端内存过滤，也可结合接口能力。
5. 新增【收藏】功能：逆向网页原有收藏API；支持对选中课程执行收藏操作。
> 注意：不实现课表解析与可视化课表界面；替换一个按钮【跳转选课网页】，点击调用系统默认浏览器打开 `[http://bkxk.szu.edu.cn/](http://bkxk.szu.edu.cn/)`。
6. **课程列表持久化**：成功拉取到的课程列表，本地持久化存储（json文件）；程序启动时优先加载本地缓存课程列表，再由用户手动刷新更新；缓存文件存放于项目根目录，日志记录缓存读写成功/失败。

### 标签页2｜抢课任务管理器
1. 任务列表，每个任务独立配置；支持任务的**新增、删除、修改**。
2. 每个任务可配置项：
    - 目标课程（课程号/课程总号）；
    - 抢课轮询频率；**单任务轮询间隔下限强制201ms，用户配置小于201ms时自动钳位为201ms，输出日志警告**
    - **独立开关选项：当课程检测到已满，是否停止本任务【满课后停止 / 满课继续轮询】**。
3. 任务状态展示：等待中 / 运行中 / 抢课成功 / 已停止 / 异常失败。
4. **全局异步请求队列模块**硬性限流约束：1秒内最多5条网络请求，等价单条请求最小调度间隔201ms；定义常量`REQUEST_INTERVAL_MS = 201`，全部硬编码常量集中放置在配置模块，方便后续修改
    - 队列最大待处理请求数量上限常量`MAX_QUEUE_SIZE = 10`；队列已满时拒绝加入新请求，输出日志告警。
    - 队列调度逻辑：每`REQUEST_INTERVAL_MS`时间从队列取出1个任务执行网络请求；所有aiohttp网络请求**全部必须经过该全局队列，禁止绕过队列直接发起http请求**。
    - 请求优先级规则：
      1. 最高优先级：用户手动触发操作（手动刷新课容量、手动收藏等UI点击操作）；优先调度执行
      2. 普通优先级：自动抢课轮询产生的后台请求
    - 多抢课任务产生的网络请求全部送入该全局限流队列；任务之间逻辑独立，但网络受全局队列限流管控。
5. **抢课任务持久化**
    - 程序关闭时，将全部抢课任务配置（目标课程、轮询间隔、满课停止开关、任务状态）序列化写入本地JSON文件；
    - 程序启动自动读取本地JSON，恢复所有抢课任务配置；**恢复后任务默认状态为【已停止】，不会自动后台运行，需要用户手动开启任务**；
    - 文件存放在项目本地，读写异常输出日志。
6. 多任务异步运行，基于aiohttp异步模型；业务任务逻辑相互独立，网络请求受全局请求队列统一限流。

### 标签页3｜日志面板
1. 日志文本显示框，每条日志格式：`[时间戳] [来源模块] 日志内容`
    - 来源模块示例：【课程查询】【抢课任务】【收藏】【系统】【请求队列】
2. 日志过滤器：复选框，勾选控制界面展示哪些类型日志，例如：抢课成功、抢课失败、查询信息、系统信息、队列调度。
3. 日志同时**持久化写入本地日志文件**保存。

## 四、接口逆向开发约束（Vibe求证阶段重点）
1. 没有现成API文档，需要解析网页JS、分析浏览器Network请求，提取：课程查询接口、课程收藏接口、抢课选课接口；可参考`szu/`目录下参考仓库api，**必须抓包校验，不能直接复用参考代码**。
2. ✅**Vibe编写、求证、推演阶段红线：AI只允许输出报文结构、参数、header样例、伪代码；禁止生成会直接执行选课/退课真实写请求的可执行调用代码；求证过程不能触发真实写接口请求。**
    - 查询类接口：可以做逻辑推演、报文构造，**不强制AI执行真实网络请求**；
    - 选课/退课写接口：**仅做报文模板构造、打印待发请求内容，代码增加总开关，默认禁用真实http提交，只做日志输出模拟，不发送真实请求**。
3. 选课提交接口仅做请求报文构造模板，**代码内部增加注释提醒使用者，自行承担调用风险，测试不要启用真实提交选课逻辑**。
4. 所有http headers组装结合szu仓库示例 + 浏览器抓包结果；studentCode、electiveBatchCode、cookie、token根据接口实际需要放到header / query / body，不要全部统一塞进某一处，以网页实际请求为准。

## 五、架构与编码规范
1. **严格模块化开发，职责拆分**
    - `config.py`：全部常量定义（REQUEST_INTERVAL_MS=201，MAX_QUEUE_SIZE=10等）、路径定义、**增加开发开关：ENABLE_WRITE_API=False，默认关闭选课/退课写请求；只有用户手动修改为True才允许发起写接口**
    - `auth_model.py`：身份凭证数据类，studentCode / electiveBatchCode / token / cookie
    - `request_queue.py`：全局异步优先级请求队列模块，限流、入队、调度、优先级逻辑，完整文档注释
    - `api_client.py`：aiohttp网络封装层，所有http请求统一由此发出，强制走请求队列；封装各个接口报文构造；**写接口处判断`ENABLE_WRITE_API`，关闭时只打印报文、写日志，不发送真实网络请求**
    - `task_model.py`：抢课任务数据模型，序列化/反序列化，用于持久化json读写
    - `course_model.py`：课程数据模型，课程列表持久化读写逻辑
    - `ui_main.py`：PyQt6界面主窗口，各个标签页UI、信号槽；不直接写网络逻辑，调用上层模块
    - `logger_util.py`：日志工具，同时输出UI面板 + 本地日志文件，日志过滤逻辑
    - `main.py`：程序入口，风险弹窗、初始化各个模块，启动Qt事件循环与异步事件循环
2. 每个模块、类、公开函数必须写**文档字符串注释**，说明入参、返回值、功能，便于后续人员修改维护。
3. 数据持久化全部使用JSON格式，不要二进制；读写文件增加异常捕获，IO错误输出日志，不直接崩溃程序。
4. Git提交要求：每实现一块独立功能就做一次独立commit，commit message清晰说明变更内容，不要一次性提交大量修改。

## 六、非需求（求证版）
1. 不做账号登录，不处理人机验证码；studentCode、electiveBatchCode、token、cookie全部由用户外部浏览器登录后复制粘贴。
2. 不再实现课表解析渲染功能，只保留网页跳转按钮。
3. **求证阶段禁止真实调用选课、退课写接口；代码默认禁用写接口，仅保留报文模板。**

## 七、补充细节
1. 网络异常、请求报错输出到日志面板。
2. 全部网络请求使用异步 aiohttp，所有http请求必须经过全局请求队列，禁止绕过限流直接发送请求。
3. 凭证输入框空值校验：发起网络请求前检测studentCode / electiveBatchCode / token / cookie，任意为空直接拒绝入队，输出警告日志。
4. 队列满的时候新增请求直接丢弃并写日志，不阻塞UI界面。
5. 单任务轮询间隔用户输入小于201ms，自动钳位到201ms并记录日志。
6. 程序启动恢复抢课任务，任务加载完成状态统一置为【已停止】，不会自动跑抢课。
7. 课程列表本地缓存：只有接口拉取成功才覆盖本地缓存；启动优先读缓存展示表格，用户手动刷新才更新。
