# 需求文档（v2 · 简要）

> 分支：`master-tampermonkey-v2`　｜　状态：**需求待你确认，尚未开始编码**
>
> 这是一份**简要**需求，只写"要做什么"，不写实现细节。
> 与 v1（`master-tampermonkey`）的关系：**v1 代码不直接沿用**，只复用其已验证的接口结论（见开发文档 §五）。

---

## 一、项目定位

深大选课站点（<http://bkxk.szu.edu.cn/>）的**油猴脚本**（Tampermonkey）辅助工具，在浏览器里运行。

- 仅供技术学习研究
- 写接口默认关闭，由使用者显式打开
- 一切使用风险由使用者自负

## 二、运行形态（已由用户确认，沿用 v1 结论）

只在两种场景、由用户**主动在前台**运行时使用：

1. **开始抢课**
2. **满课统一释放**

因此：**不做后台常驻**，不处理标签页定时器节流，不做 Service Worker / offscreen 之类机制。

## 三、功能需求与优先级

| 优先级 | 需求 | 说明 |
| --- | --- | --- |
| **P0（最高）** | **优化课程列表显示** | 让用户"更容易看见课程"。**具体呈现方式由用户提供，不自行设计** |
| P1 | 悬浮窗：管理抢课任务 | 任务增删改、启停、优先级、日志、倒计时 |
| P2 | 自定义课程 | 用于课表显示 + 计入冲突计算 |
| P2 | 课表页显示自定义课程 | 页面 `*default/curriculum.do` |

> ⚠️ 与 v1 相比的变化：**"优化课程列表"从第二优先提到了最高**。

## 四、必须满足的约束（用户明确提出）

1. **有疑问必须先提问** —— 用户是最终解答者，**不得自行猜测后开工**
2. **每轮开发结束必须暂停**，向用户索要真机测试结果，不得自行继续下一轮
3. **测试从简** —— 这是很小的项目，不需要很强的健壮性；不做覆盖率追求
4. **体积要小** —— 不接受 v1 那种 200KB+ 的产物
5. 勤提交 git

## 五、明确不做

- 不做登录、不处理人机验证码
- 不持久化凭证（token / cookie / 学号）
- 不做后台静默运行、不自动启动任务
- 不做多标签页协调、数据版本迁移、兼容层这类"大项目"机制
- 不做退课、收藏（**除非用户明确要求**）
- 不做"诊断回传包 / 页内自检"这类重型排错设施（v1 遗留物）
