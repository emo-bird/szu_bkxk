# 接口逆向记录（取证版）

> 本文档记录通过**真实请求**得到的站点行为证据，替代「照搬参考仓库」。
> 全部探测均为**只读**请求（页面、查询类接口、登录态检查、公开静态 JS），
> **未发起任何选课 / 退课写请求**。凭证经环境变量传入临时脚本，未写入仓库。

## 一、测试纪律（血泪教训，务必遵守）

**站点对高频请求会直接终止登录会话。**

排查早期，我在未做节流的情况下连续发出多条请求（单脚本 6~8 条无间隔），
随后同一组凭证立即失效，我据此误判为「用户提供的凭证是旧的」——
**实际是我自己的高频请求把该会话踢掉了**。

**因此：任何人工测试、探测、脚本都必须经过项目自身的全局请求队列**
（`config.REQUEST_INTERVAL_MS = 500ms`）。
`tools/probe_api.py` 已改为强制走 `RequestQueue`，不再直连 aiohttp。

## 二、鉴权机制（实测结论）

| 组合 | 结果 |
| --- | --- |
| token 请求头 + cookie | **200，正常返回业务数据** |
| token 请求头，**去掉 cookie** | **401**（HTML 错误页） |
| 未登录 / 会话被踢 | 接口返回 `{"code":"302","msg":"未查询到登录信息"}` |
| 未登录（页面类请求） | `302 → *default/index.do`，AJAX 请求则 `401` |

**结论**：

1. 接口鉴权需要 **cookie 与 token 同时提供**，缺一不可；
2. **token 走 HTTP 请求头 `token`**（站点 JS `BH_UTILS.doAjax(url, params, method, requestOption, headers)`
   的第 5 个参数即 jQuery `headers`）；
3. **页面跳转**的 token 走 **URL query**（`grablessons.do?token=`）；
4. 每个接口 URL 统一附加 **`?timestamp=<13位毫秒>`**；
5. 请求还需携带 `X-Requested-With: XMLHttpRequest`、`Referer`（选课子页面）、`Origin`。

> ### ⚠️ 重要更正
> 早期我用 `student/check/login.do` 是否返回「认证失败」来判断登录态，**这个判据是错的**。
> 实测同一组凭证、同一次运行中：`check/login.do` 返回
> `{"code":"#E2140600091","msg":"认证失败"}`，而 `programCourse.do` **正常返回了课程数据**。
> 判断登录态应以**实际业务接口**的返回为准。

### 3.2 分页是 **0 基** ——「接口未返回任何课程数据」的根因

| 请求 | 真实返回 |
| --- | --- |
| `pageNumber=0, pageSize=10` | `code=1`，`totalCount=11`，**dataList=10 条**，`tcList` 合计 28 条 |
| `pageNumber=1, pageSize=10` | `code=1`，`totalCount=11`，**dataList=1 条**（第 11 条） |
| 原实现：`pageNumber=1, pageSize=100` | 偏移量 100 远超总数 11 → **dataList 为空** |

原实现从 `pageNumber=1` 开始且 `pageSize=100`，导致偏移超过总记录数，
服务器返回**空 `dataList` 的合法响应**（无异常、无 msg），前端于是显示
「接口未返回任何课程数据」。现改为 `QUERY_FIRST_PAGE=0`、`QUERY_PAGE_SIZE=10`。

### 3.5 课程卡片 DOM 结构（注入显示教学班ID 用）

`js/grablessons/grablessons.js` 的 `getHtml(_data)` 负责生成课程卡片，实测结构：

```html
<div id="<教学班ID>_courseDiv" class="cv-course-card" canselect isFull isConflict isChoose ...>
  <div class="cv-info">
    <h5><span class="cv-info-title" title="<教师>">[<课程序号>]<教师></span> ...</h5>
    <div class="cv-caption-text" id="<教学班ID>_capacity">...</div>
    <div><img class="collection-img" type="collected|nocollection"
              tcId="<教学班ID>" courseNumber="<课程号>" src="..."></div>
  </div>
  <div class="cv-operate">
    <button class="cv-btn cv-btn-chose" tcId="<教学班ID>">...</button>
  </div>
</div>
```

**关键点（踩过的坑）**：`tcId` **不在** `.cv-course-card` 根元素属性上，
而在子元素 `.collection-img` / `.cv-btn-chose` / 退选按钮上；
根元素 `id` 形如 `<教学班ID>_courseDiv`，容量元素 `id` 形如 `<教学班ID>_capacity`。
渲染函数里 `var tcId = _data.teachingClassID;` 后由
`.replace('@tcId', tcId)` 逐个填入模板。

因此「在卡片上显示教学班ID」的取值必须**三级回退**：
根属性 → 子元素 `[tcId]` → 根 `id` 去掉 `_courseDiv` 后缀。

> **踩过的两个坑（都已修复并单测）**：
>
> **坑 1 — `tcId` 不在根元素上**：第一版注入脚本只读 `.cv-course-card` 根属性，
> 实测 `{"cards":13,"tags":0}`，13 张卡片全被跳过。
> 真实取值必须三级回退：根属性 → 子元素 `[tcId]` → 根 `id` 去掉 `_courseDiv` 后缀。
>
> **坑 2 — 真实 DOM 属性名是全小写 `tcid`**：HTML 解析器会把属性名小写化
> （实测渲染结果：`tcid=` 84 处，驼峰 `tcId=` 仅 2 处、位于脚本字符串内）。
> 好在 HTML 文档里 `getAttribute('tcId')` 与 `querySelector('[tcId]')`
> 都会自动按小写匹配，所以按驼峰写也能取到值 —— 但不要用
> `element.attributes` 遍历去比对驼峰名，那样会漏。
>
> **坑 3 — `Page.addScriptToEvaluateOnNewDocument` 的执行时机**：
> 该脚本在新文档**骨架建立之前**执行，此时 `document.documentElement` 仍是 `null`，
> `new MutationObserver(...).observe(document.documentElement, ...)` 会抛异常，
> 导致其后的 `setInterval` 与首次 `tag()` **全部不执行**。
> 现象极具迷惑性：`hookInstalled=true`（函数开头的标志已置位）但 `tags=0`。
> 修复：把启动逻辑包进 `boot()`，骨架为空时用 `setTimeout` 重试，
> 并额外监听 `DOMContentLoaded`；同时对**当前文档**再执行一次同样的脚本（幂等）作为双保险。

**离线验证**：用模拟 DOM（`documentElement=null` 起始）单测了 4 个用例——
延迟启动、骨架就绪后重试、重复执行幂等、`DOMContentLoaded` 兜底，全部通过。

### 3.6 卡片高度与「添加到抢课任务」按钮

**卡片高度**：站点原样式是**固定高度**且没有 `overflow` 处理：

```css
.cv-course-card { width: 244px; height: 210px; padding: 16px; box-shadow: ...; border-radius: 8px; }
```

因此追加「教学班ID」标签后内容会**溢出到卡片外**。修复方式是注入样式覆盖：

```css
.cv-course-card { height: 252px !important; }
```

用固定值而非 `height:auto`：卡片在「确认选择」模式下会切到 `.cv-operate` 并隐藏
`.cv-info`，若用 auto 会导致卡片高度跳变。

**课程名称等字段的位置**：卡片自身只有教师/时间/容量，课程级信息在同级的
`.cv-row` 容器上，可用 `card.closest('.cv-row')` 取到：

| 字段 | 选择器 | 字段 | 选择器 |
| --- | --- | --- | --- |
| 课程名称 | `.cv-course` | 课程性质 | `.cv-nature` |
| 课程号 | `.cv-num` | 开课单位 | `.cv-department-col` |
| 课程总号 | `.cv-courseTotalNumber` | 学分 | `.cv-credit-col` |
| 课程类别 | `.cv-type` | | |

**网页 → Python 的单向通道**：用 CDP 的 `Runtime.addBinding`。注册后页面里即出现
`window.__szuAddTask(字符串)`，JS 调用时本端收到 `Runtime.bindingCalled` 事件；
按钮点击回调里 `stopPropagation()` 以避免触发卡片自身的「确认选择」逻辑。

> 这样**不需要** WebView2 的 `postMessage`/`WebMessageReceived`，
> 也就不需要 pythonnet 事件订阅与 Qt 主线程互操作 ——
> pythonnet 只负责创建与摆放窗口，全部数据面（含网页回传）都走 CDP。

**离线验证**：模拟 DOM 下按钮注入、点击回传、payload 抓取（10 个字段齐备）全部通过；
假 CDP 服务下 `Runtime.addBinding` / `take_bindings` / 请求体关联
（`querySetting` → `teachingClassType` 精确取到 `XGXK`）/ 任务自动填充 共 7 项全部通过。

### 本轮发现并修复的缺陷

1. **扁平结构字段解析错误（重要）**：`publicCourse.do`（校公选/慕课）返回扁平结构
   （无 `tcList`），原实现在取教学班 ID / 容量时只看嵌套的 `tc_info`（此时是空字典），
   导致 `teachingClassID`、`classCapacity` 全为空 →
   `has_free_seat()` **恒为真 → 可能对已满课程发起抢课**。
   已改为统一从「课程级 + 教学班级级」合并后的字典取值。
2. **类别无可选课程时提示过于模糊**：辅修课程返回「该学生没有辅修课程」时，
   界面只显示「接口未返回任何课程数据」。现已把服务器业务说明透出到状态栏。

### 仍需注意

- `课程时间` 为空属正常：部分网络课程（MOOC 类公选）的 `teachingPlace` 为 `null`。
- 验收所用凭证在测试后已失效，需重新复制才能自行在 UI 上验证。

## 七、复现方式

```powershell
$env:SZU_COOKIE = "<从浏览器复制的完整 cookie>"
$env:SZU_TOKEN  = "<sessionStorage.token>"
$env:SZU_STU    = "<学号>"
$env:SZU_BATCH  = "<electiveBatchCode>"
.\.venv\Scripts\python.exe tools\probe_api.py
```

该工具**强制走项目请求队列（500ms 间隔）**，默认只发 2 条查询请求，
不含任何写接口调用。若要临时用别的方式测试，**务必自己保证 ≥500ms 间隔**。
