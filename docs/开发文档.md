## 一、项目一句话

一个 Windows 桌面工具（PyQt6 + asyncio + aiohttp），围绕深圳大学选课站点提供三件事：
**查课程**、**抢课**、**监控多个志愿的容量释放**；并可选地**内嵌官方选课页**（WebView2 + CDP）
用于登录与被动取数。当前版本 **v0.3.1**。

**最重要的一条纪律**：所有对学校站点的 HTTP 请求都必须经过全局限流队列（默认 500ms/条）。
站点对高频请求会直接终止登录会话 —— 早期未节流的探测把凭证踢掉过多次。

## 二、架构分层

```
┌──────────────────────── Qt 主线程 ────────────────────────┐
│ main.py            风险弹窗 → 日志器 → 启动窗口与异步运行时 │
│ ui_main.py         MainWindow + 4 个标签页 + 各面板         │
│                    UiBridge：把后台线程结果用 Qt 信号回主线程│
└───────────────▲───────────────────────────┬───────────────┘
                │ Qt 信号（跨线程安全）      │ _run_async(coro)
┌───────────────┴───────────────────────────▼───────────────┐
│                 asyncio 线程（AsyncRuntime）               │
│ task_model.GrabTaskRunner  轮询/监控/提交                   │
│ api_client.ApiClient       报文构造 + 唯一 HTTP 出口         │
│ request_queue.RequestQueue 单调度协程，500ms/条，优先级排序   │
└───────────────────────────┬───────────────────────────────┘
                            │ aiohttp
                    学校站点（只读 + 写接口）
```

内嵌网页旁路（**与上面链路完全独立，运行期不参与业务**）：

```
WebView2 窗口(pythonnet)  ←── CDP WebSocket ──→ webview_bridge（常驻泵）
      │                                              │
      └─ 官方选课页（用户登录）              cookie/sessionStorage/页面回传
                                                     ↓ Qt 信号
                                             凭证回填 / 课程回流 / 弹任务窗
```

**设计取舍**：pythonnet 只负责"创建并摆放窗口"，**所有数据面走 CDP**。这样即使 pythonnet /
HWND / DPI 出问题，也只是少一个标签页，不影响取数与抢课。CDP 路由的备选方案（外部 Edge）
保留在 `tools/spike_edge_login.py`。

## 三、模块地图

| 文件 | 职责 | 关键点 |
| --- | --- | --- |
| `config.py` | 全部常量、路径、开关、运行期设置读取 | 唯一配置源；`APP_DIR`（可写）/`RESOURCE_DIR`（打包只读）分离 |
| `auth_model.py` | 凭证模型：校验、归一化、脱敏、sessionStorage 模拟 | 凭证**不落盘**，只在内存 |
| `logger_util.py` | 日志：文件落盘 + UI 推送；`LogFilter` 分类过滤 | 推送前**不过滤**，由面板决定显示 |
| `request_queue.py` | 全局优先级限流队列（唯一调度出口） | `asyncio.PriorityQueue(maxsize)`；每 500ms 取一条 |
| `api_client.py` | aiohttp 封装、报文构造、响应分类 | **唯一 HTTP 出口**；写接口受总开关守卫 |
| `course_model.py` | 课程模型、容错字段映射、筛选、缓存读写 | `_FIELD_CANDIDATES` 多候选字段表 |
| `task_model.py` | 任务模型、持久化、轮询/监控执行器 | 两种任务类型：`grab` / `monitor` |
| `ui_main.py` | 主窗口、4 个标签页、对话框、信号桥 | 所有界面逻辑；不构造任何 HTTP 报文 |
| `main.py` | 入口：风险弹窗、组件装配、双事件循环 | `AsyncRuntime` 管理后台 loop |
| `webview_host.py` | WebView2 窗口宿主（pythonnet + Core API） | 只管窗口；`PYTHONNET_RUNTIME=coreclr` |
| `webview_bridge.py` | 内嵌网页数据面：CDP 泵、注入、会话迁移 | 常驻泵 100ms 轮询，点击回传 ~100ms |
| `cdp_bridge.py` | CDP 客户端（零第三方依赖） | 复用 aiohttp 的 WebSocket |
| `tools/probe_api.py` | 只读接口探测（走限流队列） | 排查接口用 |
| `tools/spike_edge_login.py` | 外部 Edge + CDP 备选路线 | A 路线回退验证 |
| `tools/spike_webview2_embed.py` | 内嵌方案 7 项独立验收工具 | 真机自检的"金标准"脚本 |
| `tools/publish_release.py` | 一条命令创建 GitHub 发行并上传成品 | 版本号取自 `config.APP_VERSION` |

依赖方向（禁止逆向依赖）：

```
main → ui_main → {task_model → api_client → request_queue → aiohttp, course_model}
                → {webview_host, webview_bridge → cdp_bridge}
task_model / course_model → {logger_util, config}
```

`task_model` **不** import 任何 webview/cdp 模块 —— 任务运行期与内嵌网页无关。

## 四、线程模型与跨线程约定

| 线程 | 内容 | 规则 |
| --- | --- | --- |
| Qt 主线程 | 所有控件、对话框、`QTimer` | **不得**直接 await 网络；用 `MainWindow._run_async(coro)` |
| asyncio 线程 | 队列、ApiClient、任务轮询、CDP 泵 | **不得**直接碰控件；用回调 → `UiBridge` 信号 |

跨线程回传统一走 `UiBridge`（`ui_main.py` 顶部的 `QObject`）：

```python
# 后台线程侧（安全，Qt 信号自动排队）
self.bridge.logRecord.emit(record)
# 主线程侧
self.bridge.logRecord.connect(self.log_panel.append_record)
```

**槽函数绝不能抛异常**（PyQt 对槽内未捕获异常会直接 abort 进程）。现有代码里槽函数、`QTimer`
回调、`paint/resizeEvent` 一律 `try/except` 兜底：`WebContainer.resizeEvent`、`WebViewHost._poll_tasks`、
`inbox_timer`、`watch` 等。

## 五、配置体系（两层）

**第一层：`config.py` 常量**（编译进程序，改它要重新打包）

- 站点与端点：`BASE_URL`、`EP_*`、`EP_VOLUNTEER` / `EP_DELETE_VOLUNTEER` / `EP_CAPACITY`
- 查询：`QUERY_FIRST_PAGE = 0`（**0 基**）、`QUERY_PAGE_SIZE`、`QUERY_MAX_PAGES`、`COURSE_QUERY_PLAN`
- 限流：`REQUEST_INTERVAL_MS = 500`、**`REQUEST_INTERVAL_FLOOR_MS = 200`（硬下限，不可调低）**、
  `MAX_QUEUE_SIZE`、`REQUEST_TIMEOUT_SECONDS`
- 优先级：`PRIORITY_MONITOR_HIT = -10` > `PRIORITY_HIGH = 0` > `PRIORITY_NORMAL = 10`（数值越小越先）
- 轮询：`MIN_POLL_INTERVAL_MS = REQUEST_INTERVAL_MS`、`DEFAULT_POLL_INTERVAL_MS`
- 任务：`TASK_KIND_GRAB` / `TASK_KIND_MONITOR` / `TASK_KIND_COLUMNS`、`MONITOR_MAX_CLASSES = 20`
- 响应码：`RESP_CODE_SUCCESS/BUSINESS_ERROR/UNAUTHENTICATED`、`UNKNOWN_RESPONSE_DUMP_LIMIT`
- 内嵌网页：`ENABLE_EMBEDDED_WEBVIEW`、`SHOW_COURSE_QUERY_TAB`、`WEBVIEW_DEBUG_PORT`、
  `WEBVIEW_BINDING_NAME`、`WEBVIEW_CARD_HEIGHT_PX`、`WEBVIEW_RELOAD_COOLDOWN_MS` 等

**第二层：`settings.json`**（与 exe 同级；开发时项目根目录）

优先级：**环境变量 `SZUBKXK_ENABLE_WRITE_API` > `settings.json` > 源码默认值**。
共 13 项，清单与安全设计见 README「十四、运行期设置」。

解析规则（`config._as_bool/_as_int/_as_float`）：

- 值无法识别 / 文件不存在 / JSON 损坏 → **一律回退默认值**；
- 数值一律**钳位**到安全区间（`request_interval_ms` 最低 200）；
- **刻意不用 `bool(value)`** —— 字符串 `"false"` 会被判为真，这是安全开关上最危险的错误；
- `bool` 不当整数用（`true` 不会变成 `1`）；
- 拼错的键会被 `UNKNOWN_SETTINGS` 抓出来并在启动日志告警。

```powershell
cd C:\Project\szu_bkxk
```

依赖：`PyQt6`、`aiohttp`、`pythonnet`、官方 WebView2 SDK（解压到 `vendor/webview2/`，已 gitignore）。

创建信号管道而被拒。这些都需要提权或在普通终端里执行。

## 七、编码约定

1. **中文 docstring + 类型注解**：所有模块/类/函数都有中文 docstring，参数与返回用 `:param:` / `:return:`；
   文件头 `from __future__ import annotations`，注解用内建泛型（`list[str]`、`dict[str, int]`）。
2. **不写无信息注释**，但要写清"为什么"：踩过的坑、反直觉的取值、约束来源，都留在 docstring 或行内注释里。
3. **异常分型**：`NotAuthenticatedError`（登录失效 → 任务停止并提示重登）、`ApiError`（业务错误）、
   `QueueFullError`（队列满 → 丢弃并告警）、`MissingCredentialsError`。
4. **日志用常量**：`config.SOURCE_*` + `config.CATEGORY_*`，不要在调用处写裸字符串。
5. **不打印凭证**：日志允许写请求网址与表单内容，**绝不写请求头**（含 Cookie/token）；
   `format_enroll_report` 对 Cookie/token 只留前 8 字符 + 长度。
6. **控制台中文**：Windows 中文控制台是 GBK，**不要**在 `print` 里用 `✓`/`✗`（会直接崩），
   统一用 `[OK]`/`[FAIL]`。
7. **改文件优先用脚本**：本工作区的 `edit` 工具对 CRLF 文件与中文 docstring 锚点较脆弱，
   涉及多行中文改动用一个临时 Python 补丁脚本（ASCII 锚点 + 唯一命中校验）更稳。

## 八、扩展指南（照抄这些步骤）

### 8.1 新增/修改接口端点

1. `config.py` 加 `EP_XXX`；
2. `api_client.py` 加报文构造（纯函数，便于单测）+ 调用方法（`await self._queue.submit(lambda: self._post_form(...))`）；
3. 响应处理**必须**走统一分类：`classify_response_text()` → `ok` / `business` / `unauthenticated` / `unknown`；
   `unknown` 必须调 `dump_unknown_response()` 全量落档；
4. 写操作必须放在 `if not config.ENABLE_WRITE_API:` 之后，并在关闭时打印报文模板；
5. 用真实抓包核对报文（逐字段），并把结论写进 `docs/接口逆向记录.md`。

### 8.2 新增任务类型

1. `config.py` 加 `TASK_KIND_XXX` + `TASK_KIND_TEXT` + 该类型的列定义进 `TASK_KIND_COLUMNS`；
2. `task_model.py`：`GrabTask` 加字段并在 `to_dict/from_dict` 往返（**向后兼容**：缺失字段要有默认值）、
   `columns()` 返回对应列；`GrabTaskRunner._run_task` 里按类型分派到新的 `_poll_xxx_once`；
3. `ui_main.py`：`TaskTable(logger, kind, ...)` 直接复用（表格/按钮/统计已通用），
   `TaskDialog` 里按 `kind` 决定显示哪些字段；
4. `TaskPanel` 无需改动（它按 `kind` 自动分发）；
5. 补离线单测：用替身 client 断言"调了哪些接口、什么优先级、什么顺序"。

### 8.3 新增设置项

1. `config.py` 的 `SUPPORTED_SETTINGS` 加键名；
2. 在对应常量处改成 `_as_bool/_as_int/_as_float(SETTINGS.get("键"), 默认值, minimum=..., maximum=...)`；
3. `settings_default.json` 加同默认值（**必须与代码默认值一致**，有离线校验）；
4. README「十四、运行期设置」表格加一行；
5. 写不写 `settings.json` 都应得到同样的默认行为 —— 这是回归测试的必测项。

### 8.4 新增页面注入逻辑（内嵌网页）

约束两条（都踩过）：

- 注入脚本经 `Page.addScriptToEvaluateOnNewDocument` 在新文档**骨架建立前**执行，
  `document.documentElement` 仍是 `null` —— 必须延迟启动（`boot()` + `DOMContentLoaded` + 定时重试），
  否则 `MutationObserver.observe(null)` 抛异常，后续 `setInterval` 与首次 `decorate()` 全部不执行；
- 卡片根元素 `.cv-course-card` **没有** tcId 属性（真实属性名全小写 `tcid`，挂在子元素上，
  根元素 id 形如 `<教学班ID>_courseDiv`），取值需三级回退。

新增注入逻辑后，对 `tools/spike_webview2_embed.py` 的探针脚本加对应自检项，并在真机上跑一遍。

### 8.5 新增日志分类

`config.CATEGORY_*` 加常量 → 加进 `LOG_CATEGORIES` → `LogPanel` 会自动多一个复选框
（面板按 `LOG_CATEGORIES` 生成）。注意：日志**文件**始终记录全部分类，过滤只影响面板显示。

## 九、怎么验证（离线优先）

本项目大部分逻辑可以**不联网、不开浏览器**验证，这是刻意设计的：

| 手段 | 用在哪 | 例子 |
| --- | --- | --- |
| 假 CDP 服务（aiohttp WebSocket） | `cdp_bridge` / `webview_bridge` | 模拟 `Runtime.evaluate`、`Runtime.bindingCalled`、`Network.*` |
| 替身 client | `task_model` 轮询/监控逻辑 | 记录"调了哪些接口、什么优先级、什么顺序" |
| 直连函数 | 报文构造 / 响应分类 | `build_enroll_param` 与 HAR 逐字段比对 |
| offscreen Qt | 界面构建与交互 | `QT_QPA_PLATFORM=offscreen`，断言表头/按钮/清单解析 |
| 子进程 + 临时 settings.json | 配置解析 | 断言钳位、类型陷阱、坏 JSON 回退 |

写临时校验脚本的**惯例**（也是本次开发全程用的）：

- 脚本名 `_xxx_check.py`，跑完即删；
- 输出目录用工作区内 `_itest_out/`（系统临时目录在沙箱下**不可写**）；
- 断言计数 + 末尾打印 `共 N 项，通过 M 项`，便于一眼看结论；
- 中文输出在 GBK 控制台会变乱码，**断言看 `[OK]`/`[FAIL]`，不要靠肉眼看中文**。

真机才能验的部分：WebView2 内嵌、CDP 连通、`tools/spike_webview2_embed.py` 的 7 项自检。

## 十、踩过的坑（改相关代码前先读）

| # | 坑 | 结论 |
| --- | --- | --- |
| 1 | pythonnet 默认走 netfx 会加载失败 | `os.environ.setdefault("PYTHONNET_RUNTIME", "coreclr")` 必须在 `import clr` **之前** |
| 2 | `'int' cannot be converted to System.IntPtr` + PyQt abort | 显式 `System.IntPtr(hwnd)`；槽函数包 `try/except` |
| 3 | WebView2 异步创建死锁 | **不能**阻塞等 `.NET Task`；用 `QTimer` 轮询 `IsCompleted`（要泵消息） |
| 4 | 高 DPI 下画面错位 | `controller.Bounds` 用**物理像素**，并设 `RasterizationScale = DPR` |
| 5 | 注入脚本不执行 | 新文档阶段 `documentElement` 为 null → 延迟启动（详见 8.4） |
| 6 | 卡片取不到教学班ID | tcId 在**子元素**上，三级回退（详见 8.4） |
| 7 | 卡片内容溢出 | 站点固定 `height:210px` 且无 overflow → 注入 `height:252px !important` |
| 8 | 课程号带"课程详情" | `.cv-num` 内有 `<span class="cv-detail">`，克隆节点剔除后再取文本 |
| 9 | `tcList` 的 `null` 覆盖课程级字段 | 合并时只取非 `null`（`{k: v for k, v in tc.items() if v is not None}`） |
| 10 | 点击网页按钮后要等十几秒 | 回传读取不能排在耗时步骤之后 → **常驻消息泵**（100ms） |
| 11 | 真实浏览器打开无课程 | 只传 token 不够，选课页会 `JSON.parse(sessionStorage.getItem('studentInfo'))` → 必须整体复制 sessionStorage |
| 12 | 重复启动真实浏览器断连 | Chromium 对同一 user-data-dir 是单例 → 先 `is_cdp_alive()` 探测，已有实例就复用 |
| 13 | 重新载入选课页报"系统异常" | 必须带 `?token=`（站点 JS 原文如此） |
| 14 | 日志筛选勾了没反应 | `Logger` 推送前就过滤了，面板拿不到被过滤的条目 → 改为**全量推送 + 面板过滤 + 即时重绘** |
| 15 | 会话日志一秒一条 | 会话快照每秒刷新且无条件记录 → 按指纹**去重**，只在真变化时记一条 |
| 16 | 页面导航不受限流约束 | 「重新载入」加 1.5s 冷却、「在真实浏览器打开」加防重入（方法级守卫，不只禁用按钮） |
| 17 | PowerShell 发 JSON 被 GitHub 422 | `Invoke-RestMethod` 传非 ASCII 不可靠 → 改用 Python 显式 UTF-8 + `urllib` |
| 18 | 中文锚点匹配不上 | 多行中文改动改用 ASCII 锚点 + 唯一命中计数的补丁脚本 |

## 十一、打包与发布

打包：`build.bat`（PyInstaller，产物 `build\szu_bkxk\`，约 150 MB；zip 后约 53 MB）。
要点：

- `--add-data "vendor\webview2;vendor\webview2"` 把 SDK 打进去；
- `--collect-all pythonnet --collect-all clr_loader` + `--hidden-import clr`（运行时动态导入，静态分析看不到）；
- 冻结后 `Path(__file__)` 指向临时解包目录 → `config.APP_DIR`（exe 同级，可写）/ `RESOURCE_DIR`
  （包内 `_MEIPASS`，只读）分离，日志/缓存/任务配置/profile 都落在 exe 旁边；
- 打包最后一步把 `settings_default.json` 复制成成品的 `settings.json`；
- `build/` 与 `dist/` 都在 `.gitignore`，**二进制不进版本库**，走 Release 附件分发。

发布：`tools/publish_release.py`（详见 README「十三 → 发布到 GitHub」）。

## 十二、不要做的事

- ❌ 绕过 `RequestQueue` 直接发请求（哪怕"只读"、哪怕"就一次"）；
- ❌ 把 `REQUEST_INTERVAL_FLOOR_MS` 调低，或给设置项放开这个下限；
- ❌ 把 `ENABLE_WRITE_API` 默认值改成 `True`，或去掉写接口守卫；
