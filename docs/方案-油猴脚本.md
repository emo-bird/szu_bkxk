## 一、目标与范围

### 1.1 一句话

把现有桌面版（PyQt6 + aiohttp + WebView2/CDP）的能力**重做为浏览器内的油猴脚本**：
用户正常登录站点后，脚本在其页面内提供**抢课任务悬浮窗**，并增强课程列表与课表显示。

### 1.2 需求与优先级（源自用户明确指定）

| 优先级 | 需求 | 说明 |
| --- | --- | --- |
| **P0** | **网页悬浮窗：管理抢课任务** | 最高优先。任务增删改、启停、优先级、日志、倒计时 |
| **P1** | **优化课程列表显示** | 让课程更容易被看见。**具体方案保留，后续提供**；本方案只定"数据层 + 扩展点" |
| **P2** | 增加**自定义课程** | 最低优先。用于**课表显示**与**冲突计算** |
| **P2** | **课表页显示自定义课程** | 目标页 `*default/curriculum.do` |

### 1.3 明确不做（本分支首版）

- ❌ 不实现登录、不处理人机验证码（用户自己登录）
- ❌ 不持久化凭证（`token` / cookie 一律运行时现取）
- ❌ 不后台静默运行（见 §二）
- ❌ 不复用桌面版任何 Python 代码（只复用其**结论与证据**）
- ⏸ 收藏 / 退课任务化：端点已知，暂不实现（可作后续）

## 二、前提结论：运行形态（已由用户确认）

用户研究抢课规则后得出结论：**只有两种应用场景**——

1. **开始抢课**（批次开放瞬间开始提交）；
2. **满课统一释放**（满课课程在某个时间点统一放量）。

因此脚本**只在特定时间段、由用户主动在前台打开页面运行**。
→ **不存在后台标签页定时器节流问题**，不需要 Worker / Service Worker / `offscreen` / `alarms` 等常驻方案，
也不需要处理"浏览器关闭后仍在抢"的能力。整个架构因此可以做得非常简单。

**这条前提必须写进代码注释与 README**，因为它解释了"为什么不追求常驻"。

## 三、技术选型

### 3.1 油猴脚本形态

| 项 | 取值 | 理由 |
| --- | --- | --- |
| `@match` | `http://bkxk.szu.edu.cn/xsxkapp/sys/xsxkapp/*` | 覆盖 `grablessons.do` / `curriculum.do` / 查询页等全部站点子页 |
| `@run-at` | `document-idle` | 站点依赖的库与 DOM 已就绪，减少竞态 |
| `@noframes` | 声明 | 站点可能用 iframe，避免重复注入 |
| `@grant` | **`none`（页面上下文）** | 必须能直接访问 `window.jQuery`、`BH_UTILS`、`sessionStorage`、并 hook `fetch`/`XHR` |
| 存储 | `localStorage` + `sessionStorage` | `@grant none` 下无 `GM_setValue`；站点同源，`localStorage` 天然可用且随页面同域 |

> **为什么必须页面上下文**：站点自身的 Ajax 封装是 `BH_UTILS.doAjax(url, params, method, requestOption, headers)`
> （见逆向记录 §二），课程数据也在页面 JS 的内存里。要复用它们、要被动取数，就必须在页面上下文。
> 代价是拿不到 `GM_*` API；由 `localStorage` 替代即可。

### 3.2 复用站点自带库（用户指定）

站点已加载：`jQuery@2.1.1`、`Chart.js@2.5.0`、`FlipClock.js`、`SockJS`、`Stomp.js`、
`Sortable@1.3.0`、`jQWidgets`、`jquery.nicescroll`、`jquery.base64`。
脚本**优先复用这些库**，不重复打包同类依赖。

| 库 | 计划用途 | 备注 |
| --- | --- | --- |
| **jQuery 2.1.1** | 悬浮窗 DOM 构建与事件绑定 | 站点就是它；直接 `window.jQuery` |
| **jQWidgets** | 任务表 / 日志表（可选） | 站点表格组件，视觉一致；但 API 与主题 CSS 较重，**首版可只用原生表格** |
| **Sortable 1.3.0** | 任务**拖拽排序**（即优先级顺序） | 与"按列表顺序提交"联动 |
| **FlipClock.js** | **抢课开始 / 放量时间的倒计时** | 与两种场景天然契合，强烈建议用 |
| **Chart.js 2.5.0** | 任务统计（成功/失败/请求数） | 可选，非核心 |
| **jquery.nicescroll** | 悬浮窗内滚动条 | 可选 |
| **jquery.base64** | 编解码辅助 | 仅在确有需要时用 |
| **SockJS + Stomp** | **待侦察**：站点是否有容量/放量推送通道 | 若有，可显著降低轮询频率（见 §十二 未决项） |

**三条硬约束**：

1. **核心逻辑不得依赖任何站点库**——`queue` / `api` / `time` / `store` 必须是纯原生 JS。
   站点升级库或改版时，核心抢课能力不受影响。
2. **必须特性探测，不能假定存在**。这些库可能异步加载、可能只出现在部分页面。
   统一走 `waitFor(() => window.jQuery)` 探测 + 超时降级到原生实现。
3. **绝不能 `@require` 再引一份同版本库**——会与站点自己的实例冲突（插件重复注册、事件重复触发）。

### 3.3 源码组织与打包

**结论：源码分模块 + 轻量构建脚本拼接为单文件 `.user.js`。**

```
src/…            # 模块源码（每个文件一个 IIFE/导出约定）
scripts/build.mjs  # 拼接 + 注入 @version/@updateURL → dist/szu_bkxk.user.js
dist/szu_bkxk.user.js
```

理由：Tampermonkey 单文件安装体验最好；`@require` 引外部 raw 文件会引入网络依赖与缓存问题。
构建脚本只需做字符串拼接与元数据注入，不引入 npm 依赖（保持零依赖）。

## 五、数据与状态

### 5.1 会话（现取现用，不落盘）

| 项 | 来源 | 说明 |
| --- | --- | --- |
| `token` | `sessionStorage.token` | 每个请求放 HTTP 头 `token`；页面跳转放 URL `?token=` |
| 学生信息 | `sessionStorage.studentInfo`（JSON） | `studentCode` 等 |
| 当前批次 | `sessionStorage.currentBatch`（JSON） | `code`（= `electiveBatchCode`）、`schoolTerm` |
| cookie | **不读取** | 同源 `fetch` 由浏览器自动附带（含 HttpOnly） |
| 服务器时间 | 响应体 `timestamp` 字段 / `Date` 响应头 | 用于**时间偏移校正**（见 §七） |

> **凭证红线**：`token`/cookie **绝不写入 `localStorage`**、绝不进日志。
> 日志只允许写"请求网址 + 表单内容"，**禁止写请求头**（沿用桌面版约定）。

### 5.2 `localStorage` 结构（命名空间 `szubkxk.`）

```
szubkxk.settings       # 脚本设置（写开关、默认间隔、面板位置…）
szubkxk.tasks          # 抢课任务列表
szubkxk.customCourses  # 自定义课程（P2）
szubkxk.cache.courses  # 课程数据缓存（含保存时间）
szubkxk.logs           # 面板日志（环形缓冲，上限条数）
szubkxk.schemaVersion  # 结构版本，用于未来迁移
```

- 全部读写 `try/catch` 兜底，**任何 IO 异常都不得让脚本崩溃**（沿用桌面版约定）。
- 结构变更时必须走 `schemaVersion` 迁移，旧数据缺失字段一律给默认值（向后兼容）。
- **`tasks` 恢复后状态一律为"已停止"**，绝不自动运行（沿用桌面版约定）。

### 5.3 统一数据模型

沿用逆向记录 §3.3 的字段表，做成**多候选容错映射**（对应桌面版 `_FIELD_CANDIDATES`）：

- 课程级：`courseName / courseNumber / courseTotalNumber / courseNatureName / departmentName / credit / typeName / tcList`
- 教学班级级：`teachingClassID / teacherName / teachingPlace / classCapacity / numberOfFirstVolunteer / isFull / isConflict / isChoose / isFavorite / isMooc / mainClassCapacity / mainElectiveNumber`
- **关键坑必须继承**（逆向记录 §五）：
  - `publicCourse.do`（校公选/慕课）**返回扁平结构、没有 `tcList`**，一行即一个教学班；
    → 取值必须"课程级 + 教学班级级合并"，否则 `teachingClassID`/容量为空 → **余量判断恒为真 → 对已满课程发起抢课**。
  - `capacity.do` 的 `classCapacity`/`numberOfFirstVolunteer`/`isFull` **可能全为 `null`**；
    → 余量判断要用 `mainClassCapacity - mainElectiveNumber`。

## 六、功能设计

### 6.1 P0 · 悬浮窗（任务管理器）

**宿主形态（待评审的取舍）**

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| A. 普通顶层 `div` + 命名空间前缀类名 + 局部样式重置 | 可直接复用站点库组件与主题；实现简单 | 站点全局 CSS 可能渗透、`!important` 冲突 |
| B. Shadow DOM 隔离 | 绝对不受站点 CSS 影响 | 站点库（jQWidgets 主题）的 CSS **不会**进入 shadow root，需手工搬运；与"复用站点库"目标冲突 |

> **建议：先 A**（与"复用站点自带库"的要求一致），把类名统一加前缀（如 `.szubkxk-*`）＋ 局部 `reset`；
> 若实测被站点样式严重干扰，再对该子树改 B。**列为待评审决策点。**

**面板能力**

- 拖动、边缘吸附/折叠、展开/收起；位置、尺寸、折叠态持久化。
- 最高 `z-index`；不遮挡站点关键按钮（默认停靠右下角）。
- 内容分区：
  1. **任务区**：任务表 + 新建/编辑/删除 + 开始/停止 + 拖拽排序（Sortable）。
  2. **倒计时区**：距离开始抢课 / 放量时间的倒计时（FlipClock）。
  3. **日志区**：分类过滤、`[未识别返回]` 高亮。
  4. **设置区**：写开关（含风险提示与二次确认）、默认间隔、面板开关。
- 键盘：`Esc` 收起；可选快捷键唤出。

### 6.2 P0 · 任务与两种场景

**任务模型**

```js
{
  id, name,
  kind: 'grab' | 'monitor',        // 开始抢课 / 满课统一释放
  startAt: <epoch ms | null>,      // 精准到时（服务器时间基准）
  targets: [ { teachingClassId, courseNumber, courseName, teacher, teachingClassType } ],
  intervalMs,                      // 轮询间隔，下限 = 全局请求间隔
  fullStrategy: 'stop' | 'keep',   // 满课后停止 / 继续轮询
  enabled: false
}
```

- **`grab`（开始抢课）**：到达 `startAt` 前只做**只读**探测（`capacity.do` / 列表），
  到时后按 `targets` 顺序尝试提交；成功即结束该目标。
- **`monitor`（满课统一释放）**：持续/定时探测目标余量，**命中即提交**，不因满课停止；成功即结束。
- **命中判定（只读、轻量优先）**：优先 `elective/teachingclass/capacity.do`（body `teachingClassId` + `batchCode`），
  余量 = `mainClassCapacity - mainElectiveNumber`；必要时回退整页列表的 `isFull`。
- **提交顺序**：目标列表顺序（可由 Sortable 拖拽调整），不要伪装成并发。
- **停止条件**：成功 / 用户停止 / 登录失效（`code=302`）/ 达到请求预算上限 → 明确状态与原因。
- **写入开关关闭时**：只**构造并打印报文**（面板日志），**不发出任何写请求**（沿用桌面版红线）。

### 6.3 P1 · 课程列表优化（**方案待用户提供，此处只留架构**）

本节**不预设视觉方案**，只确定"无论最终方案是什么，都需要的东西"：

1. **课程数据层**（`data/capture` + `data/model`）：hook 页面自身的 `fetch`/`XHR`，
   **被动旁听**站点已经发出的查询响应（零额外请求，沿用桌面版设计），归一化为统一模型。
2. **三个扩展点**（未来每次改动只动其中一处）：
   - ① **渲染器接口** `renderCourseListCtx(ctx)`：拿到归一化课程数组 + 挂载点，自行决定怎么呈现；
   - ② **排序/筛选纯函数**：输入课程数组 → 输出新数组（便于单测）；
   - ③ **标记接口** `decorateCard(node, model)`：给卡片/行加余量、冲突、收藏等角标。
3. **候选方向**（仅备查，**待用户给定的方案覆盖**）：
   信息补全（教学班ID、余量、冲突）、紧凑/列表视图切换、按余量或时间排序、
   只看有余量、一键加入任务、收藏标记。
4. **评价标准**：不破坏站点原交互；可一键整体开关；站点改版时改动能收敛到上述扩展点内。

### 6.4 P2 · 自定义课程 + 冲突计算

**数据模型**

```js
{
  id, name, teacher, place, color,
  sessions: [ { weekStart, weekEnd, weekParity: 'all'|'odd'|'even',
                weekday, periodStart, periodEnd } ]
}
```

**教学时间解析器**（`core/time`）

把站点字段 `teachingPlace`（形如 `5-18周 星期二 3-4节 致理楼L1-707`）解析为归一化 `sessions`。
必须处理的变体（**每条都要有单测**）：

- 单/双周（"单周""双周"字样）；
- 连堂与多节次（`3-4节`、`3节`、`3,4节`）；
- 一门课**多段**时间（分隔符不固定）；
- MOOC / 网络课程 `teachingPlace` 为 `null`（**属正常**，逆向记录 §五已确认）；
- 分隔符与全角/半角空格差异。

**冲突计算**（纯函数）

站点课程与自定义课程**归一到同一 `sessions` 结构**后做区间相交：
`周次区间相交 && weekday 相等 && 节次区间相交`。
输出：冲突列表 → 用于 ① 课表高亮 ② 悬浮窗提示 ③（可选）课程列表标记。

### 6.5 P2 · 课表页注入自定义课程

- 目标页：`http://bkxk.szu.edu.cn/xsxkapp/sys/xsxkapp/*default/curriculum.do`
- **M0 侦察项**（必须先看清）：课表容器 DOM、是否 jQWidgets grid、单元格坐标模型、
  站点自身课时块的类名与定位方式。
- 注入策略（首选）：**按解析出的 `sessions` 计算格子坐标 → 叠加自定义块**，
  **不修改站点数据、不调用站点接口**。
- 样式：虚线边框 / 角标区分"自定义"，与站点原有课程视觉可辨。
- 幂等与重渲染：用 `MutationObserver` 监听课表容器，**变更后重注入**（桌面版踩过的"注入不生效/被覆盖"坑）。
- 冲突：在同一格同时存在站点课程时加冲突标记。

## 七、抢课调度：服务器时间对齐（本方案的关键点）

用户是"在特定时间段前台运行"，那么**"几点几分开始"的准确性**就是核心质量指标。本机时钟可能有偏差。

1. 从任意响应中取**服务器时间**（响应体 `timestamp` / `Date` 头）；
2. 计算并缓存 `offset = serverNow - performance.now()`，定期（低成本）刷新；
3. 所有 `startAt` 一律以**服务器时间**为基准换算成 `performance.now()` 目标点；
4. 到时触发用 `setTimeout` + **漂移校正**（醒来后比对偏差，必要时重新对齐）；
5. **提前量**：允许配置"提前 N 毫秒开始发只读探测"，但**写请求严格不早于 `startAt`**。

> 倒计时 UI（FlipClock）显示的是**服务器时间**，而不是本机时间。

## 八、红线与安全（一字不改地继承桌面版）

1. **写接口默认关闭**：`settings.writeApiEnabled = false`。关闭时只构造并打印报文，**绝不发送**。
   开启需在 UI 中**显式二次确认**，并显示风险说明。**默认值不得改成 true。**
2. **限流不可绕过**：所有站点请求经 `core/queue`，默认 **500ms/条**；
   **硬下限 200ms**（与桌面版一致，任何设置都不得低于它）。此规则同样适用于"只探测"。
3. **凭证不落盘**：`token`/cookie 只在内存/`sessionStorage`；日志**不写请求头**。
4. **未识别返回全量落档**：既非 `code=1` 成功、也非 `code=2` 业务拒绝、也非登录失效的响应，
   一律输出 `[未识别返回]` + 请求体 + 响应原文，作为"边用边补"的反馈回路。**不得删除该机制。**
5. **前台、用户主动、不自动运行**：不后台静默、不随页面刷新自动启动任务；页面重开后任务一律"已停止"。
6. **使用声明**：仅供技术学习研究；禁止大规模恶意抢课；首次使用弹出风险提示。
